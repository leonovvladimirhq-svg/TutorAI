# Важные решения

Почему проект устроен именно так. Новое — сверху. Формат: дата · решение · почему · что из этого следует.

---

### 2026-10-04 · Бэкап и единая документация
Одна ветка `main`; отложенная ветка — тегом `archive/qwen3.6-apikey-2026-06-30`; устаревшие
документы — в `docs/archive/`; знания из локальной памяти ИИ-ассистента перенесены в
`CLAUDE.md` и `docs/`. **Почему:** через полгода проект должен подниматься с GitHub без догадок.
Регламент команды по Yandex Cloud (документ Ивана) в публичный репозиторий не кладём — там
инфраструктура других проектов; нужное TutorAI пересказано в `CLAUDE.md`.

### 2026-09-29 · Режим теста: каждый наставник видит всех студентов
Переключатель в панели (`app_setting mentors_see_all`), сейчас включён. **Почему:** на тесте
никто не будет закреплять студентов за наставниками вручную, а без закрепления наставник
никого не видит. После теста — выключить: вернётся закрепление (`app_user.mentor_tg`).
Новая цель уходит всем наставникам, решает ответивший первым.

### 2026-09-29 · В «Мои студенты» — только приславшие хотя бы одну цель
**Почему:** пустой список должен однозначно значить «никто ещё ничего не прислал».

### 2026-09-18 · Вебхук вместо long-polling, HTTPS через Yandex API Gateway
**Почему:** в long-polling MAX присылает голосовые пустым `message_created` (без сообщения) —
голос до бота не доходит; через вебхук доходит (проверено живым тестом). MAX требует HTTPS на
443 с доверенным сертификатом — своего домена нет, поэтому шлюз YC. **Следствие:** после
простоя проверять шлюз и подписку (RESTORE.md, раздел Б); polling остаётся запасным режимом.

### 2026-09-18 · Вход по 16-значным кодам доступа
Коды генерирует руководитель в панели (набор: 8 студентов / 2 наставника / 1 руководитель),
роль «зашита» в код. **Почему:** не собирать MAX-ID у каждого студента вручную. `/forget_me`
освобождает код — тот же код можно ввести заново и начать с чистого листа.

### 2026-09-18 · Голос: транскрипция MAX → иначе ffmpeg → SpeechKit
**Почему:** SpeechKit v1 принимает только OggOpus/LPCM, а MAX отдаёт другой контейнер.
Определяем контейнер по сигнатуре, перекодируем ffmpeg (он в `Dockerfile.max`).

### 2026-09-18 · `/forget_me` — полный сброс
Удаляются профиль, цели, рефлексия **и регистрация**; `consent_record` остаётся аудитом (152-ФЗ).
**Почему:** на тесте нужно «начать как будто впервые».

### 2026-09-15 · Модуль наставника по протоколу заказчика (п. 3.3, 3.4)
Согласовано с Леоновым: рефлексия — кнопка в меню + напоминание по сроку; наставник
подтверждает цель сразу после постановки (с причиной при отклонении); сроки — в панели;
отдельного шага «план действий» нет (хватает A в SMART). Закономерности — сначала студент,
потом сводка ИИ. Степень достижения цели **не оценивается** — только глубина рефлексии.
Доуточнений — не больше 1 на вопрос и 3 на цель, вопросы можно пропустить, итоги — завершить.

### 2026-09-10 · Кнопка «Оставить как есть» в SMART-разборе
**Почему:** студент не должен застревать в бесконечном коучинговом цикле.

### 2026-07-28 · Переезд с Telegram на MAX
**Почему:** из Yandex Cloud Telegram заблокирован (ТСПУ/фильтрация подсетей); обход через
прокси — вопрос 152-ФЗ и «игра в кошки-мышки». MAX из YC доступен. Отдельный образ
(`Dockerfile.max`): maxapi и aiogram несовместимы по aiohttp. Код Telegram-версии оставлен
(`app/bot`, `app/main.py`), но не запускается; тексты `app/bot/texts.py` общие.

### 2026-07-24 · Статический IP из «рабочего» диапазона
**Почему:** до части IP-диапазонов YC (51.250.x, 93.77.x) трафик не доходит — SSH виснет.
Перевели VM на `89.169.157.225`.

### Владелец облака · docker маскируется при каждой загрузке VM
`bootcmd: systemctl mask docker…` в user-data (Иван, после инцидента, когда стек «душил» VM
и SSH был недоступен). **Почему:** SSH гарантированно жив после перезагрузки. **Следствие:**
после каждой перезагрузки стек поднимают вручную (RESTORE.md, раздел Б). Менять — только с Иваном.

### 2026-07-21 · Согласие 152-ФЗ версионируемое, данные — только в РФ
Двухэкранное согласие (`app/legal/consent_tutorai_v1.md`); при смене версии запрашивается
заново; аудит — таблица `consent_record`. LLM и STT — в Yandex Cloud, данные не уходят за рубеж.

### 2026-06-29 · Стек и архитектура
Python + PostgreSQL + Docker на одной VM; LLM и STT — сервисы Yandex Cloud (GPU не нужен).
Профиль студента со статусом подтверждения: в профиль попадает только то, что студент
подтвердил. Исходный план — `docs/archive/TutorAI_План_реализации.md`.
